# 2026-10-20

## Sitio web PoliMusic - clon Spotify en ASP clásico

Se creó la aplicación web completa en ASP clásico (VBScript, NO ASP.NET/C#) en
`webapppolimusicv1_asp/`.

### Decisiones técnicas
- **Motor**: ASP clásico con extensión `.asp`, VBScript. Conexión ADODB vía
  `Provider=SQLOLEDB.1` a SQL Server 2025 (`localhost`, BD `BDD_PoliMusic`,
  usuario `usr_polimusic` / `Politecnica1`, definidos en `BDD_PoliMusic.sql`
  que está en la carpeta padre `Web_Avanzadas/`).
- **Restricción respetada**: no se crearon tablas nuevas; solo se usan las del
  script (`TBL_SONG`, `TBL_USER`, `TBL_ALBUM`, `TBL_ARTIST`, `TBL_PLAYLIST`,
  `TBL_TRACKLIST`, `TBL_PLAYER`, `TBL_PLAYLIST_SONG`, `TBL_CATALOG`).
- **Includes planos en la raíz** (`conexion.asp`, `funciones.asp`, `header.asp`,
  `footer.asp`). Se descartó la subcarpeta `includes/` porque ASP resuelve las
  rutas de `#include` de forma ambigua y rompía la carga de funciones.
- **Roles**: `USER_TYPE` 0 = normal, 1 = admin. El CRUD de `TBL_SONG` exige
  `ExigirAdmin`; el contador de `PLAYS` solo exige `ExigirSesion`.
- Al borrar una canción se eliminan primero las filas hijas
  (`TBL_PLAYLIST_SONG`, `TBL_TRACKLIST`, `TBL_PLAYER`) por las FK.

### Diseño
Paleta propia (no verde Spotify): índigo/violeta profundo con acentos ámbar y
rosa. CSS en `css/polimusic.css`, JS del reproductor en `js/polimusic.js`.
Layout tipo Spotify: sidebar + contenido + barra de reproductor fija.

### Bugs encontrados y corregidos durante la validación
1. Faltaba el `%>` de cierre en `conexion.asp`, `funciones.asp` y
   `canciones_accion.asp` (rompía todo el sitio).
2. `canciones_accion.asp` exigía ADMIN también para `accion=play`, lo que
   impedía a los usuarios normales sumar reproducciones.
3. La consulta de álbumes destacados agrupaba mal
   (`al.ID_ALBUM` fuera del `GROUP BY`) → error SQL 8120.

### Validación realizada
- Script propio `.workbuddy-ai/tmp/validar_asp.py`: balance de bloques
  VBScript (`If/End If`, `Do/Loop`, `Function/End Function`, etc.) e includes.
- Script `.workbuddy-ai/tmp/probar_sql.py`: ejecuta las 8 consultas del sitio
  contra la BD real. Todas pasan.

### Pruebas / despliegue (pregunta del usuario: "¿cómo pruebo el sistema?")
- `conexion.asp` ahora prueba 4 proveedores en cadena (`MSOLEDBSQL`,
  `SQLOLEDB.1`, `{ODBC Driver 17 for SQL Server}`, `{SQL Server}`) y muestra el
  detalle del error de cada uno si ninguno sirve. Motivo: en ASP clásico el
  proveedor disponible depende de si el pool es de 32 o 64 bits.
- Se agregó `prueba_conexion.asp`: diagnostica motor ASP, conexión ADODB,
  conteo de filas de las 9 tablas, resolución de los 5 assets clave y estado de
  sesión. Es la primera página que hay que abrir tras desplegar.
- Se agregó `desplegar_iis.bat` (raíz): xcopy a `C:\inetpub\wwwroot` + `icacls`
  para `IIS_IUSRS`/`IUSR`. Debe ejecutarse como administrador; verifica con
  `net session` y aborta si no hay elevación.
- `preview_local.html` es la vista previa estática generada desde la BD real,
  para ver el diseño sin IIS.

## Bug: "Ocurrio un error al consultar la base de datos" en login.asp

El usuario despliego el sitio en IIS y el login siempre fallaba con ese mensaje.

**Causa raiz:** `Consulta()` en `conexion.asp` hacia
`Set rs = cn.Execute(sql)` y luego `Set rs.ActiveConnection = Nothing`.
`Connection.Execute` devuelve un recordset *forward-only*; asignarle
`ActiveConnection` lanza "Operation not allowed without a current recordset".
Como la conexion SI abria bien, `Conectar()` no reportaba nada y el error
salia encapsulado como el mensaje generico de `login.asp`.

**Fix:** `Consulta()` ahora usa `Recordset.Open` con
`CursorLocation = adUseClient (3)` y `adOpenStatic (3), adLockReadOnly (1),
adCmdText (1)`. Con cursor del lado del cliente el recordset queda
independiente de la conexion y se puede cerrar `cn` de inmediato.
Se agregaron las constantes ADO en `conexion.asp`.

**Mejoras de diagnostico (para no volver a ver errores genericos):**
- `Const MODO_DEBUG = True` en `conexion.asp` (poner False antes de entregar).
- `MostrarErrorBD(mensaje, numErr, txtErr)` en `funciones.asp` escribe la
  alerta amigable + un `<details>` con el error real de ADODB/SQL Server.
- `ConsultaSegura(sql, mensajeError)` y `EjecutarSeguro(sql, mensajeError)`.
- `login.asp`, `canciones.asp`, `albumes.asp`, `playlists.asp` ya usan
  `ConsultaSegura`; `canciones_accion.asp` usa `EjecutarSeguro`.
- `prueba_conexion.asp` tiene una seccion nueva que prueba `Consulta()`
  exactamente igual que el sitio.
- Guards `IsObject(rs)` en vez de `Not rs Is Nothing` (falla si rs esta Empty).
